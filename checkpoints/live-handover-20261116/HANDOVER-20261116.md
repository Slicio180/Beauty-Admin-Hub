## Automatic player recovery

Implemented in LivePlayerRecovery.js and authenticated Hub routing. It runs while an authorised organiser is signed in and the Hub is visible; no independent background trigger is installed.

Checks bind to the selected event, context revision, roster, player identity and original saved operation. Shared locks/leases prevent overlapping work. An uncertain write is inspected through its original receipt rather than blindly repeated.

Automatic categories: registration review, saved-operation review and eligible missing event entry. Transient unavailable/busy/stale checks have limited retry handling. One active check owns the player record. OUT and STANDBY are not automatically transferred. Closed-event handling does not reopen the event.

Identity conflicts, uncertain removals, profile creation requiring explicit confirmation, older operations and unverified outcomes need the appropriate review path. The engine is player-centred, not a universal data-repair engine. Green means that particular outcome was verified.

The original handbook now contains the approved flow diagram and Resolve issue steps. Mermaid source was saved and read back; rendered Page preview has not been visually checked.
